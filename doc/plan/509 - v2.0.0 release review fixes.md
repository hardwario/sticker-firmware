# v2.0.0 release review fixes

PR [#509](https://github.com/hardwario/sticker-firmware/pull/509) into `v2.0.0`. Source: the
release review of PR [#503](https://github.com/hardwario/sticker-firmware/pull/503) (head
`059ac313`), defects 1–7 plus the lower-severity points. Decisions taken for this PR:
v2.0.0 is the new baseline (no downgrade is supported), `APP_PROTO_VERSION` stays `0x01`.
Release notes: `doc/version 2.0.md` §53.

## Defects

| # | Defect | Fix | Test |
|---|---|---|---|
| D1 | Stillness rule (`from 0 to 0` on PIR / accel motion) fires with the capability off: the latch sweep in `app_alarm_poll()` checked `last_rule.enabled`, not whether the rule is armed. One activation ~`dwell` after boot, never cleared. | The sweep checks `app_alarm_rule_armed(&last_rule)`, like every other evaluation path. | `alarm_eval` `test_stillness_rule_inert_without_capability` |
| D2 | RATE on hall / input counters read `g_app_sensor_data` (refreshed per `interval-sample`), so `dwell` < `interval-sample` gave one activate/deactivate pair per sample tick. | `read_counter()` reads hall L/R and input A/B totals live (`app_hall_get_data()`, `app_input_get_data()`). PIR / accel counters were already live. | `alarm_eval` `test_rate_reads_live_counter_not_sample_cache`; RATE tests now drive the live counter |
| D3 | 11 B tier (US915 DR0 / AU915 DR2, 10 B protobuf): a group over the page budget (two NA sentinels = 12 B, the barometer, or the system group on a page that also carries `page_index` / `page_count`, 6 B) was sent alone, refused by the MAC with `-EMSGSIZE`, lost every report. | `G_SYSTEM` is packed first. A group that does not fit an empty page is split field by field (`tlm_cursor.split_g` / `split_sent`). A field or 1-Wire reading that fits no empty page is skipped with `LOG_WRN`. `layout_pages()` counts only non-empty pages, so `page_count` stays exact. NA values are still lost at this tier (6 B each, a wire change would be needed). | `compose` `test_na_sentinels_at_11_byte_tier`, `test_group_split_at_11_byte_tier`, `test_w1_at_11_byte_tier`, `test_w1_reading_bigger_than_page_skipped` |
| D4 | `APP_PROTO_VERSION` 0x01 for both v1.4 and v2.0 encodings. | **No change** (decision). Release notes: a mixed-fleet decoder selects by the Info fw version. | — |
| D5 | §21 claimed v1 history survives the upgrade; since #431 no v1 page mounts. | Doc only: §21 and Upgrading item 7. | — |
| D6 | v1.4 `alarm-N` blobs (17 B, now 18 B) fail the size check with `-EINVAL` before the stale-key path: 16 `set-value failure ... error(-22)` lines every boot until a manual save. | `config.c.j2`: a known key with another stored size is a stale key (`LOG_WRN`, deleted after a clean load, parameter keeps its default). `STALE_KEYS_MAX` 4 → 8. `h_set` keys only select variable + size; one shared check/read (flash neutral). | pytest (template ↔ `app_config.c` in sync); HIL H6 |

## Security review (v2.0.0, 2026-10-14)

Follow-up review of the same branch (`059ac313`), verified against the code. Decisions:

| # | Finding | Decision |
|---|---|---|
| R-3 | `lrw_reset` reachable over a radio; it deletes `lorawan/nvm/Crypto` incl. the OTAA DevNonce, so a 1.0.4 NS refuses the node's later joins. | **Fixed**: `transports: [nfc, shell]`. Test `cmd` `test_lrw_reset_and_calibration_not_over_radio`. |
| C-1 | `enter_calibration` (`[lrw, nfc]`) and `SetParam.application.calibration` (no `writable:`) reachable over a radio; calibration uplinks under the fleet-shared ABP keys of `app_calibration.c`. | **Fixed**: `enter_calibration` `[nfc, shell]`, `calibration` `writable: [shell, nfc]`. Same test. |
| R-1 | `fsk` P2P pairing: public `TWR_PAIRING_KEY`, first valid `JOIN_RESP` wins. | **No change**: `fsk` stays in release (TOWER compatibility). |
| N-3 | `set_secret_key` over the vendor channel is not gated by `vendor_reset_allow`. | **No change**: the vendor token may change the secret key by design. |
| R-2 | P2P gateway replay lane (`m_gw_last`) is RAM-only; the review assumed a captured downlink replays after a reboot. | **Not a defect**: the node accepts a downlink only in the window after a fresh ACK whose `acked` is its own never-used counter (`p2p_wait_ack()` → `p2p_wait_dl()`), and that ACK lifts the lane to the gateway's current counter, above every recorded frame. Nothing to persist. |
| B-2 | Supply chain: Zephyr fork pinned by SHA (M2); GitHub Actions on mutable tags, `action-gh-release` with `contents: write`. | **Fixed**: every action pinned to a commit SHA (tag in a comment), `.github/dependabot.yml` for the bumps, the release carries `SHA256SUMS`. The fork's `west.yml` pins every module by SHA already. |
| B-3 | Tag interpolated into `run:`. | Already closed by M1 (tag must match `^vX.Y.Z$` before use). |

## HIL

Bench: one STICKER per row, J-Link by explicit SN, debug build unless noted. Record board SN,
J-Link SN, image commit and PASS/FAIL per step in §53 of `doc/version 2.0.md`.

**H1 — Pulse counter (D7), both polarities.**
1. `config cap-gpio-mode inputs`, `config cap-gpio-input-a pulse`, `settings save` (reboots).
2. Drive input A from a mechanical relay (bouncy contact) wired as pull-down to GND, idle high.
   Toggle it N = 100 times at ~2 Hz from a counter or script.
3. `input_a_count` (telemetry, or `ats radio compose`) grew by exactly 100.
4. Repeat with the relay sourcing the line (idle low).
5. Repeat at ~10 Hz with 30 ms pulses (S0 timing): exactly N.
6. Boot with the line held active (pulse in progress at init), release, then N pulses: N
   (counted on trailing edges).
7. Release build, Stop2 active: same 100 pulses, count exact (the settle timer runs from
   Stop2).

**H2 — RATE on live counters (D2).**
1. `config interval-sample 60`, input A digital counter (or hall left).
2. `alarm new mb input-a-count hi 3 dwell 10`.
3. Inject 5 edges within 10 s: one activation (alarm uplink, red LED).
4. Keep injecting ≥ 3 edges per 10 s for 60 s: no deactivation, no second activation.
5. Stop: exactly one deactivation at the end of the next 10 s window.
6. Repeat with `config interval-sample 0`.

**H3 — Stillness with the capability off (D1).**
1. `config cap-gpio-mode none`, `config cap-accelerometer false`, `settings save`.
2. `alarm new mb pir-motion from 0 to 0 dwell 30` and the same for `accel-motion`.
3. Wait 5 min: no alarm frame, no red LED, no buzzer; `alarm list` shows the rules inactive.
4. Turn the capability on (`cap-gpio-mode pir`, save): the stillness rule activates after
   30 s without motion and clears on motion.

**H4 — 11 B tier (D3).** US915 or AU915 build (`lrw-region`), shell compose only, no air time
needed.
1. `cap-sht true` on a board with the SHT4x unplugged (or failed), barometer enabled, a dallas
   probe on 1-Wire.
2. `ats radio compose 11`: every page ≤ 11 B, page 0 starts with `voltage` / `system_flags`,
   pressure and altitude on their own pages, `page_count` = number of pages printed.
3. Log shows `LOG_WRN` for the skipped NA fields and the skipped 1-Wire reading, no
   `-EMSGSIZE` from the radio.
4. On air (US915 DR0 against the Hub / CS): every page is delivered and decodes with
   `ttn.js`.

**H5 — Failed save still reboots (M3).** Covered by `tests/cmd`; on HW only a smoke test:
`settings save` over NFC and over the radio reboots as before.

**H6 — Upgrade v1.4.x → this image (D6).**
1. A unit on v1.4.x with alarms configured (16 `alarm-N` keys in NVS).
2. Flash this image without erase.
3. Boot 1: `Key config/alarm-N is 17 B, expected 18 B: stale` warnings, `Stale key ...
   removed` for 8 keys, no `set-value failure ... error(-22)`.
4. Boot 2: the rest removed. Boot 3: no stale-key or set-value lines at all.
5. Identity, LoRaWAN keys and other config values unchanged (`config show` diff).

**H7 — Buzzer and PIR modes (regression of the GP-pin owner).** `cap-gpio-mode buzzer`:
alarm melody on an alarm; `cap-gpio-mode pir`: motion count and `pir-motion` alarm.

**H8 — Full release regression on the final head.** Release build, LoRaWAN EU868 and P2P
(Hub), each ≥ 2 h: join, Info + settings-info after boot, telemetry every report, an alarm
activate/deactivate, a `GetConfig` paged answer, a SetParam + reboot, no IWDG reset
(`Reset cause` on the following boot).

**H9 — R-3 / C-1 over the air.** Joined over LoRaWAN, enqueue `lrw_reset` (`0801820100`)
and `enter_calibration` (`0801920100`): each answers `Error NOT_READY`, no reboot, the unit
keeps its session. Enqueue `set_param{application{calibration=true}}` (`0801120412020801`):
`Error NOT_WRITABLE`. Then send `lrw_reset` over NFC: it acks and reboots, the next join
succeeds (on ChirpStack flush the DevNonces first).

# HARDWARIO STICKER — plaintext command transport and explicit claiming

Plan for the PR that (1) adds a **`plain_text` command transport** — a configen-enforced
allowlist of protobuf commands the device answers **without** `secret_key` — with
`get_claim_info` as its first command, and (2) turns the claim window into an **explicit,
two-state latch** (`active` from the factory / `done`) with no automatic behaviour, renaming
`clm_ack`/`clm_rearm` to `claim_done`/`claim_active`.

**Status:** plan for [PR #415](https://github.com/hardwario/sticker-firmware/pull/415)
(`feat(cmd): plain text transport and explicit claiming`, draft, into `v1.5.0`); implementation
commits follow (§7).

It is the prerequisite of the NFC mailbox PR
([#414](https://github.com/hardwario/sticker-firmware/pull/414), `doc/plan/v1.5.0_mailbox.md`):
mailbox channel 0x03 forwards to the `plain_text` transport, and removing the `hio.stck:clm`
NDEF record there needs `get_claim_info`. This PR is self-contained and shell-testable
(`ats cmd plain <hex>`), so it merges first.

> Decided 2026-09-09 in the #313 discussion (D8–D11 of the mailbox plan): claiming only into a
> powered device; a generic plaintext transport rather than a claim-specific one, so a later
> `get_basic_info` ("who am I" without the key) can reuse it; claim window controlled only by
> explicit commands; default state `active`.

---

## 1. Context — how the claim window works today

| Element | Today |
|---|---|
| State | `clm/state` in NVS: `unset` / `pending` / `consumed` (`app_nfc.c:430–432`). |
| Auto-arm | `unset → pending` on every NFC poll once `claim_token` is set (`app_nfc.c:1972`), split into an in-RAM step + deferred persist (`clm_arm_commit/revert`, #340 M3) tied to the `clm` record landing on the tag. |
| Implicit close | `pending → consumed` on **any** successfully decrypted `hio.stck:cmd` frame (`handle_encrypted_cmd`, `app_nfc.c:1487`, #308). |
| Explicit close / re-open | Commands `clm_ack` (proto 25, `[nfc, shell]`) and `clm_rearm` (proto 27, optional `new_claim_token`, always save + reboot, #351); shell `ats claim active \| done \| status` (`app_ats.c:1442–1511`). `ats claim active` sets `unset` and relies on the auto-arm. |
| Resets | `vendor_reset` → `app_nfc_clm_reset()` (`app_settings.c:468`, "like a freshly manufactured device"); `device_reset` / `factory_reset` leave the state alone. |
| Exposure | `ClaimInfo{serial_number, claim_token}` laid on the tag as the plaintext `hio.stck:clm` record while `pending` (removed by #414). Deleting it over RF no longer closes the window (#360). |
| Transports | `enum app_cmd_transport { LRW, NFC, SHELL_DEBUG, VENDOR }` (`app_cmd.h:25–33`); configen `_TRANSPORT_ENUM` (`scripts/west_commands/configen.py:835`) generates a `tp != …` guard per command from `transports:` in `app/src/app_config.yml` (`templates/commands_dispatch.c.j2:10–14`). |

## 2. Decisions

| # | Decision | Consequence |
|---|---|---|
| C1 | **New transport `plain_text`** (`APP_CMD_TRANSPORT_PLAIN_TEXT`, configen token `plain_text`). Frames on it are unencrypted protobuf `Command` → `0x01 \|\| Response`; only commands listing `plain_text` in `app_config.yml` are dispatched, every other command gets `NOT_READY "transport not allowed"` from the generated dispatch. Never reachable over LoRaWAN. | Generic "who am I / may I claim you" channel with a compile-time allowlist. Rule: a `plain_text` command must be read-only and disclose identity-class data only. |
| C2 | **`get_claim_info`** (proto id 29, empty body, `transports: [plain_text, nfc, shell]`) returns `Response.claim_info` = existing `ClaimInfo{serial_number, claim_token}` while the window is `active`; `Error NOT_READY "claimed"` when `done`; `Error NOT_READY "no claim token"` when none is provisioned. | The owner (key holder) and the tester can read it too; anonymous readers only while `active` on a powered unit. |
| C3 | **Two states, explicit only:** `active` (factory default) / `done`. Remove `unset`, the auto-arm (`:1972`), `clm_arm_commit/revert`, and the implicit close (`:1487`). Mutators: `claim_done` / `ats claim done` → `done`; `claim_active` / `ats claim active` / `vendor_reset` → `active`. `device_reset`/`factory_reset` unchanged. | No default or automatic behaviour. NVS migration: `unset`/`pending` (0/1) → `active`, `consumed` (2) → `done`. Accepted trade-off: an app that never sends `claim_done` leaves the token readable on a powered unit (ATELOS still refuses a second claim of the same SN). |
| C4 | **Rename** `clm_ack` → `claim_done` (id 25), `clm_rearm` → `claim_active` (id 27); messages `ClmAck`/`ClmRearm` → `ClaimDone`/`ClaimActive`. Wire-compatible. | Generated names change in firmware, the JS decoder (`ttn.js:183,185`) and the app's vendored proto (rewritten for #414 anyway). `guard_no_renumber_commands()` compares ids per *name*, so a rename passes silently — verify by hand that 25/27 did not move. |
| C5 | **`get_basic_info` on `plain_text`** is a candidate, not in this PR unless requested: serial, FW version, config version, claim state, mailbox availability — nothing beyond identity. | Keeps the transport generic from day one; field set to be decided. |

## 3. Design

### 3.1 Transport

- `app_cmd.h`: `APP_CMD_TRANSPORT_PLAIN_TEXT` appended to `enum app_cmd_transport`.
- `configen.py:835`: `"plain_text": "APP_CMD_TRANSPORT_PLAIN_TEXT"` in `_TRANSPORT_ENUM` (and `_ALL_TRANSPORTS`). Nothing else in configen changes: a command that does not list `plain_text` already gets the generated guard.
- Framing is the caller's job (identical to the encrypted channels minus CCM): request = raw `Command` protobuf, response = `0x01 (APP_PROTO_VERSION) || Response` (`encode_response`, `app_cmd.c:1329–1345`). No nonce, no response cache, no claim side effects.
- Callers: in this PR only the shell injector `ats cmd plain <hex>` (`app_ats.c:951`, next to `nfc`/`lrw`/`history`); #414 adds mailbox channel 0x03.
- Paging budget: `dump_page_budget()` treats `PLAIN_TEXT` like LoRaWAN's small budget (no dump command is allow-listed anyway).

### 3.2 `get_claim_info`

- `app_config.yml`: `- {name: get_claim_info, proto_id: 29, body: GetClaimInfo, kind: handler, response: claim_info, transports: [plain_text, nfc, shell]}` (check how `response:` is consumed by the decoder template; add `claim_info` where the response kinds are enumerated).
- `app_config.proto` (hand-written, outside the configen markers): `message GetClaimInfo {}`; `Response.claim_info = 9` using the existing `ClaimInfo` message (its comment rewritten: no longer an NDEF record). `ClaimInfo.claim_token` keeps `max_size:16 fixed_length:true` in `app_config.options.in`.
- `app_cmd.c`: `app_cmd_handle_get_claim_info()` — `app_nfc_claim_state_get() == DONE` → `make_error(NOT_READY, "claimed")`; `claim_token` all-zero → `make_error(NOT_READY, "no claim token")`; else fill `resp->body.claim_info` from `g_app_config`.

### 3.3 Claim latch

- `app_nfc.c`: `enum { CLAIM_ACTIVE = 1, CLAIM_DONE = 2 }` persisted under the existing `clm/state` key; loader maps legacy 0/1 → `ACTIVE`, 2 → `DONE`, anything else → `ACTIVE` (factory default when the key is absent).
- Public API: `app_nfc_claim_done()`, `app_nfc_claim_active()`, `app_nfc_claim_state_get()`; remove `app_nfc_clm_reset()`/`app_nfc_clm_ack()`/`clm_consume()`/`clm_arm_commit()`/`clm_arm_revert()`, the `just_armed` logic in `nfc_check_locked()` (`:1956–1985`) and the `clm_consume` call in `handle_encrypted_cmd()` (`:1487–1489`) with its #308 rationale (`:480–491`).
- The `hio.stck:clm` record is still laid while `ACTIVE` in this PR (`build_resting_ndef`, `:1186`) so the NDEF claim read keeps working until #414 removes the record; the arm/commit/revert dance is no longer needed because the state no longer depends on the tag write succeeding.
- `app_settings.c:468` (`vendor_reset`) → `app_nfc_claim_active()`. `main.c:175–195` (`CLM_REARM_SAVE` action) → `app_nfc_claim_active()`, action renamed `APP_CMD_ACTION_CLAIM_ACTIVE_SAVE`.
- `app_cmd.c`: handlers renamed `app_cmd_handle_claim_done()` / `app_cmd_handle_claim_active()`; behaviour unchanged (`claim_active` keeps the optional new token and the save + reboot path).
- `app_ats.c`: `ats claim active` → `app_nfc_claim_active()` directly (no more "re-arms on next poll"), `ats claim done` → `app_nfc_claim_done()`, `ats claim status` prints `active` / `done`.

### 3.4 Flows

**Production tester:** `config claim-token <hex>` + `settings save`; the state is `active` from the factory (NVS default); `ats claim status` confirms. No other step.

**App (after #414):** tap → `inf` → probe → `get_claim_info` on channel 0x03 → ATELOS `{SN, claim_token}` → `secret_key` + `vendor_token` → `claim_done` on channel 0x01 in the same session. If ATELOS refuses, nothing is closed. Owner re-reads the token any time with `get_claim_info` over the encrypted channel.

**Transitional (this PR merged, #414 not yet):** the `clm` NDEF record still shows while `active`; the current NDEF app flow reads it as before, but the window now closes only on `claim_done` (the app's `clm_ack`, same id 25) — the implicit close on the first command is gone.

## 4. What changes / what to communicate

- **Requirement change (customer):** claiming needs a powered device (mailbox), see mailbox plan D8/R27. `claiming_process.md` §1/§3 to be rewritten here (flow, explicit close, no RF-delete step).
- **App / ATELOS:** ATELOS API unchanged (`{SN, claim_token}` → keys). App must send `claim_done` explicitly; renamed commands in the vendored proto.
- **Security:** anonymous readers get `claim_token` only from a powered unit while `active` (today: from any unpowered box via the NDEF record until #414). The `plain_text` allowlist is generated, so adding a command to it is a reviewed one-line yml change.

## 5. Risks

| # | Risk | Mitigation |
|---|---|---|
| K1 | An app that crashes between the ATELOS confirmation and `claim_done` leaves the token readable on a powered unit. | Accepted (only the token leaks; ATELOS refuses a second claim of the same SN). App sends `claim_done` right after storing the keys; `ats claim done` as manual fallback. |
| K2 | A future command gets `plain_text` by mistake. | Rule in `app_config.yml` comment + review; ztest sends every non-allow-listed command on `PLAIN_TEXT` and expects `NOT_READY`. |
| K3 | Rename breaks consumers: JS decoder names (`ttn.js:183,185`, tests), Manager-App vendored proto, docs/test plans naming `clm_ack`. | Regenerate decoder + fix `ttn.test.js` here; app regenerates in the #414 lockstep MR; grep docs. |
| K4 | NVS migration of `clm/state`. | Loader maps 0/1 → `active`, 2 → `done`; ztest with a `settings` fixture for each legacy value. |
| K5 | Transitional window (this PR without #414): NDEF app relies on the implicit close. | Short window; `clm_ack`/`claim_done` (id 25) still closes it; documented in the release notes. |
